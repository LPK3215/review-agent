# RAG 生产化与排查

本页收拢 [[source/rag-total]] 第十四至十六章的运维口径；链路机制见 [[concept/rag-pipeline]]，检索层取舍见 [[concept/hybrid-retrieval]]。

## 一、部署形态

**索引与查询分离**：索引走批处理，可离线、可重跑；查询走在线服务，要低延迟、可扩容。两者共用一个向量库，但读写权限不同。^[raw/rag-total.md]

## 二、可靠性四条降级

| 场景 | 做法 |
|---|---|
| 检索服务挂了 | 降级为纯生成，并明确告知没有引用 |
| 重排超时 | 跳过精排，直接用粗排结果（重排要能降级，一个超时不该打断整条链路）| 
| 库正在重建 | 双版本并行，切流量而不是停机（即 collection 版本化）| 
| 答案被质疑 | 用 trace 回查当时召回了哪些块 |

^[raw/rag-total.md]

## 三、监控四条曲线与联合读法

看四条：检索命中率、拒答率、首字延迟、单次 token 消耗。**四条必须同看**，单看任一条都会误判：^[raw/rag-total.md]

- 命中率跌 + 拒答率涨 → 召回坏了（解析/切分/Embedding）。
- 命中率正常 + 拒答率涨 → 提示词或阈值改坏了。

评估指标与数据集口径见 [[answers/answer-rag-eval-metrics]]。^[raw/rag-total.md]

## 四、安全四道边界

| 威胁 | 场景 | 做法 |
|---|---|---|
| 库内内容含指令 | 文档里写着「忽略之前的指令」 | 片段一律当数据，只进资料区，不进系统指令区 |
| 用户输入注入 | 用户直接要求越权 | 分隔标记加声明，规则冲突以系统侧为准 |
| 越权检索 | 低权限用户问到高权限文档 | 元数据带权限字段，先过滤再检索 |
| 敏感信息外泄 | 答案里带出手机号、身份证 | 输出侧脱敏，日志不记原文 |

^[raw/rag-total.md]

脱敏正则（手机号 / 身份证 / 邮箱）要放**两处**：入库前脱敏一次，输出前再脱敏一次。只做一处，换个入口就漏。审计记五件事（谁问的、问了什么、召回了哪些文档、答案是什么、耗时多少），**审计日志本身也要脱敏**，否则变成新的泄露源。^[raw/rag-total.md]

## 五、排查顺序与症状对照

**顺序不可反：先看检索有没有捞到证据，再看生成有没有用证据，最后看组装有没有把证据挤掉。** 顺序反了会在提示词上反复调，问题其实在切分。^[raw/rag-total.md]

| 症状 | 先查什么 |
|---|---|
| 答非所问 | 召回块是否相关；不相关就是切分或 Embedding |
| 说资料不足但其实有 | 阈值过高、top_k 过小、同义改写未覆盖 |
| 答案有编造 | 提示词缺「只依据资料」，或资料里有相似但错误的内容 |
| 前后矛盾 | 同一事实在库里有两个版本，旧版没删 |
| 慢 | 先看生成阶段，再看重排候选数 |

^[raw/rag-total.md]

五个误区：Embedding 越大越好（领域失配比维度不足更常见）、top_k 越大越好（无重排时放大 K 直接掉准确率）、全库一种切分、只优化检索（提示词缺约束时检索再好也会被丢一边）、向量库能替代关系库（只解决相似性，事务与精确查询仍要关系库）。^[raw/rag-total.md]

## 六、上线清单

- 解析结果抽查过表格与跨页段落；分块参数按文档类型分组
- 每块带来源、页码与权限元数据
- 提示词里有「只依据资料」与拒答规则
- 评估集已建，改动前后跑同一批
- 有 trace，能回查每次召回了什么
- 有降级路径，检索不可用时不至于整站挂掉
